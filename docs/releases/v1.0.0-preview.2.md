# Comfy Telegram Pipeline v1.0.0-preview.2

Second preview of the MIT-licensed open-source portfolio/community project. This release packages documentation, collaboration templates, and assisted Telegram ingress configuration added after preview 1. It is not a stable or clean-install-certified release.

## Changes since preview 1

### Community and project presentation

- Explicit portfolio/community status, with no support SLA or guaranteed maintenance schedule.
- Contribution guidelines, security reporting policy, structured bug/feature forms, and a PR template.
- Maintainer guidance for Issues, private vulnerability reporting, visibility, and review practices. These settings are not enabled by adding files.

### Remote access and security

- Documented reference routing: private Tailscale Serve for the editor/approval forms; public Funnel through a restrictive Nginx gateway for Telegram updates.
- Sanitized Nginx and Compose examples preserving exact-path POST filtering, default deny, loopback host bindings, request limits, and timeouts.
- Tutorial section 6 links directly to remote-access setup, automation, and security guidance.
- Recommendations cover identity/device security, least-privilege tailnet access, private/public separation, webhook origin checks, forwarded headers, credential handling, and alternative proxies.
- README clarifies that processing/storage are local while Telegram webhook delivery uses external services.

### Assisted ingress setup

- Initialize-TelegramIngress.ps1 and configure_ingress.py prepare a new private directory outside the repository without starting services.
- Generated Manage-Ingress.ps1 separates Validate, StartGateway, ConfigureTailscale, and Status actions.
- Existing destinations, unsafe/broad webhook URLs, conflicting ports, and in-repository runtime paths are refused.
- Automatic routing refuses existing Serve/Funnel state rather than overwriting production routes. Startup refuses existing project containers instead of adopting them.
- Five new offline ingress regression tests; the PowerShell wrapper also parses the generated-runbook template.

## Validation evidence

- Five API graphs regenerated/checked locally from workflow builders.
- Eleven Python tests passed locally: two custom-node contracts, four local-configuration tests, and five ingress tests. The same eleven passed with simulated CP1252 defaults.
- The operator previously confirmed Windows PowerShell parsing and the original six tests. The added PowerShell actions and service integration were not executed on Windows in the development environment.
- YAML, documentation links/topic anchors, placeholder handling, and known private-marker removal checked locally.
- The reference operator supplied successful nginx -T output for the existing installation. This does not validate a new deployment or every generated parameter combination.

## Existing video behavior

The video flow remains first frame → LTX at 30 FPS → preview/approval → FILM 2x → RealESRGAN batch8 upscale → final publication/notification. New-job dimensions remain 1088x1920 or 1920x1088 at 60 FPS. This update does not intentionally change the existing video workflow protocol, model selection, or production runtime.

## Limitations and scope

- A complete clean installation has not been validated. The maintainer is publishing a portfolio preview, not committing to a clean-install test or support schedule.
- Templates remain inactive and unconfigured; credentials, URLs, model paths, and Error Workflow bindings must be configured locally.
- Live setup actions, Tailscale authorization/policy, and webhook origin checks require deployment-specific review. Generation of files is not a security audit.
- The routing action explicitly enables public Funnel ingress and is never part of default preparation. If a later external command fails, earlier successful changes remain; no automatic reset/rollback occurs.
- One authorized private-chat user, file-based scheduler, and documented runner/mount assumptions remain the reference design. Distributed n8n queue mode is not supported here.
- /stop affects the entire Comfy queue; Telegram delivery is not guaranteed exactly once.
- Model checksums/revisions, the exact VideoHelperSuite commit, and effective encoder versions remain incompletely pinned. nginx:stable-alpine is a mutable example tag.
- No model weights, keys, credentials, operational database/state, or private media are distributed. Third-party terms remain separate from the project's MIT license.
- CI/CD is not implemented. No production services or routes are changed by updating source/documentation files alone.

## Upgrade and installation notes

Existing operators may update documentation/community files without executing the setup helpers. Do not replace configured production workflows/custom nodes with public templates or run a second supervisor against shared state.

New users should read docs/TUTORIAL.md and docs/REMOTE-ACCESS.md before preparing private configuration. Keep runtime files outside Git and explicitly review each startup/routing action.

The preview 1 tag/assets are preserved. Preview 2 source assets must be created with git archive from the new tag. SHA256SUMS.txt identifies the attached ZIP; a checksum is not a digital signature or a guarantee against secrets.
