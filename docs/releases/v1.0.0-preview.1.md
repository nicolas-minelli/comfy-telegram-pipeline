# Comfy Telegram Pipeline v1.0.0-preview.1

First preview distribution of a local Telegram → n8n → Comfy video pipeline.

## Included

- Telegram wizard: first-frame upload, 9:16/16:9, 2/4/6/8 seconds, prompts, draft review, and submission.
- Multiple queued jobs with reservation control, checkpoint recovery, and explicit preview approval.
- LTX generation → FILM interpolation → RealESRGAN batch upscale → verified final MP4 publication.
- Draft/retry, status/queue, clear/delete, global stop, and queue recovery controls.
- Error Handler v2 and supervisor incident-notification retries.
- Five regular n8n templates, isolated T5 fixture, two project custom nodes, and five generated API examples.
- English tutorial, 44 FAQ answers with examples, SVG/PNG infographic, and local setup/diagnostic helpers.
- MIT license for original project material; third-party terms remain separate.

## Reference environment

Windows; Comfy 0.42.3; n8n 2.43.7 in Docker; VideoHelperSuite 1.7.9 (operator reported, exact commit unknown). Original hardware: RX 9060 XT 16 GB VRAM, 16 GB system RAM. This is a reference, not a universal minimum.

New-job outputs: 9:16 → 1088x1920 at 60 FPS; 16:9 → 1920x1088 at 60 FPS. See docs/MODELS.md for the six separately downloaded weights.

## Validation

The operator reported the following passing on Windows:

- PowerShell parser checks.
- Generation/checking of five API graphs from installed-workflow builders.
- Two custom-node contract tests and four local-configuration tests.

Local static localization checks preserved 380 node identities, connections, and 132 JavaScript structures. Earlier private-runtime tests do not certify a clean installation of this preview.

## Known limitations

- Clean-install end-to-end validation and live setup-helper validation remain pending.
- Public templates are inactive and unconfigured: use private prepared copies, select credentials, and bind Error Workflows before activation.
- One authorized private-chat user; file-based scheduler with specific runner, mount, and /proc assumptions. Distributed n8n queue mode is not supported by this reference design.
- Only the exact Telegram POST route should be public. UI/approval forms stay private; verify proxy/Trigger origin checks.
- /stop affects the entire Comfy queue. A dedicated instance is recommended.
- Incident delivery is not exactly once. Normal replies and final notifications do not have the same persistent outbox guarantee.
- Model revisions/checksums, VideoHelperSuite commit, and effective encoder versions are not fully pinned.
- No model weights, runtime database, credentials, keys, or production media are included.
- CI/CD is not implemented.

## Installation

Read docs/TUTORIAL.md before preparing an isolated deployment. Do not overwrite configured production workflows/plugins with inert public templates. Preserve runtime state and keys in private backups.

The release procedure scans current files and locally available Git history before tagging. A scanner pass is not a guarantee against every secret format. The release asset must be produced with git archive from the tag, not by compressing an arbitrary working folder.
